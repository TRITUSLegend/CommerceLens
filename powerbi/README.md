# Power BI layer

| Path | What it is | Status |
|---|---|---|
| `data/` (gitignored) | Star schema + reference tables as parquet, built by `scripts/build_powerbi_data.py` | VERIFIED: built and integrity-checked on the real CSVs |
| `dax_measures.md` | Every DAX measure, with the SQL file each one mirrors | LOGIC-CHECKED: each measure mirrored in pandas by `scripts/verify_powerbi_measures.py` |
| `CommerceLens.SemanticModel/definition/` | TMDL semantic model generated by `scripts/build_powerbi_tmdl.py` | **UNTESTED**: never opened in Power BI Desktop |
| `CommerceLens-theme.json` | Report theme: blue `#2a78d6` first, blues/greys after; orange `#eb6834` only through the colour measures | UNTESTED (JSON parses) |
| `requirements-powerbi.txt` | Pinned packages for the scripts above (Python 3.13) | VERIFIED |

Once the project has been saved from Power BI Desktop (`definition/database.tmdl` exists),
`scripts/build_powerbi_tmdl.py` refuses to overwrite it unless run with `--force`.

## Rebuild

```powershell
py -3.13 -m venv .venv-powerbi
.venv-powerbi\Scripts\python -m pip install -r powerbi/requirements-powerbi.txt
.venv-powerbi\Scripts\python check_data.py
.venv-powerbi\Scripts\python scripts/build_powerbi_data.py       # powerbi/data/*.parquet + integrity checks
.venv-powerbi\Scripts\python scripts/verify_powerbi_measures.py  # pandas mirror of every measure vs SQL
.venv-powerbi\Scripts\python scripts/build_powerbi_tmdl.py       # TMDL semantic model
```

This environment runs on Python 3.13 with NumPy 2.x. It is separate from the project's
`requirements.txt` (Python 3.11 pins) and needs only duckdb, pandas and pyarrow; nothing is retrained.

## Opening the TMDL semantic model (UNTESTED procedure)

The generator writes only the semantic model definition (tables, partitions, relationships,
sort-by settings, date table, measures). It does not write `database.tmdl`, `definition.pbism`,
the `.pbip` file or a report, because those carry version numbers that Desktop should write
itself. Take them from a blank project:

1. Power BI Desktop: **File > Options and settings > Options > Preview features**. If
   "Store semantic model using TMDL format" is listed, tick it and restart Desktop.
2. **File > New** (blank report), then **File > Save as**, choose *Power BI project (.pbip)*,
   and save it **outside the repo**, for example `C:\temp\pbishell\CommerceLens.pbip`. Close Desktop.
3. Check that `C:\temp\pbishell\CommerceLens.SemanticModel\definition\` exists. If you see a
   `model.bim` file instead, this Desktop build saves the older format: skip to the manual build in
   `docs/powerbi_build_checklist.md`.
4. Copy into this repo's `powerbi\` folder:
   - `CommerceLens.pbip` and the whole `CommerceLens.Report\` folder
   - into `powerbi\CommerceLens.SemanticModel\`: `definition.pbism` and `.platform` (if present)
   - into `powerbi\CommerceLens.SemanticModel\definition\`: `database.tmdl` only. Do **not** copy
     the shell's `model.tmdl`, `tables\` or `cultures\`.
5. Open `powerbi\CommerceLens.pbip`, then **Home > Refresh**. The `DataFolder` parameter points to
   this repo's `powerbi\data\` on the machine where the generator ran; if the repo has moved, use
   **Transform data > Edit parameters > DataFolder** (keep the trailing backslash).
6. If Desktop rejects a file, its message names the file and line. Note it, then use the manual build.

Once it opens, continue with step 6 of `docs/powerbi_build_checklist.md` (Reconciliation page).
